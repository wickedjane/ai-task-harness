# 실제 동작하는 프론트 만들기

기존 스택·컴포넌트·스타일·API를 읽고 재사용한다. 새 디자인 도구·프레임워크 설치는 기본 단계가 아니다. 필요한 화면만 만들고 사용자의 주요 행동이 처음부터 끝까지 이어지게 한다.

테스트 실행 선택·범위·시점은 하네스의 `skills/verify.md`를 따른다.

## 역할·계약·병렬 작업

- 역할마다 ‘보는 정보 / 수행할 행동 / 완료 결과 / 권한’을 짧게 정한다. 운영 화면은 입력·설정·결과·오류의 관계를, 개인 화면은 본인에게 필요한 결과와 다음 행동을 우선한다.
- 화면을 꾸미기 전에 API 입력/출력·단위·시간대·오류 형식·계산 상태·데이터 버전을 정한다. 정상·빈 결과·오류 응답 예시를 공유한다. 모의 데이터는 표시하고 같은 계약으로 실제 API에 교체한다.
- 세션을 나눌 때 역할·파일 소유권·지연 시 인수 절차는 하네스의 `skill-library/parallel-task-coordination/SKILL.md`에 한 번 정하고 따른다.
- 180분 예시에서는 경과 60분 안에 단순 기준안으로 첫 실제 흐름을 연결하는 것을 목표로 한다. 안 되면 장식과 고도화를 줄이고 연결부터 한다. 기능 완성 여부를 정적 스크린샷만으로 판단하지 않는다.

## 작은 디자인 시스템

- 제품의 사용자·정보 밀도·주요 행동을 기준으로 배치한다. 업무 도구라면 설명용 히어로보다 필터·입력·표·상세·주요 실행 버튼을 우선한다.
- 색·글자·간격·테두리·상태 표시를 소수의 토큰으로 통일하고 기존 브랜드 규칙이 있으면 유지한다. 주 행동은 명확히, 보조 행동은 구분한다. 같은 의미에 같은 색과 용어를 쓴다.
- 폼은 보이는 라벨·단위·허용 범위·필드 근처 오류를 제공한다. 결과의 빈 상태·로딩·실패·재시도·부분 성공을 구분하고 입력을 불필요하게 지우지 않는다.
- 긴 표는 헤더·단위·정렬·상세 진입을 읽기 쉽게 한다. 좁은 화면에서는 필요한 가로 스크롤 등으로 내용을 보존한다. overflow를 숨겨 데이터나 버튼이 잘린 문제를 가리지 않는다.
- 키보드 조작·보이는 포커스·시맨틱 버튼/폼·명확한 대비를 확인한다. 색만으로 상태를 구분하지 않는다. 모션을 넣으면 기능 이해를 돕는 범위로 하고 reduced-motion을 고려한다.
- 수치·차트는 실제 응답에서 만들고 기간·단위·버전을 표시한다. 시험용 데이터와 모의 데이터는 식별한다. 차트의 내용을 확인할 수 있는 표/텍스트도 제공한다.

## 상태와 실제 동작

- 중복 실행을 막고 요청 중임을 알린다. 설정을 바꾼 뒤 이전 결과를 새 결과처럼 표시하지 않는다. 늦게 도착한 이전 요청의 응답이 최신 결과를 덮지 않게 한다.
- 역할별 화면은 같은 저장된 결과를 조회한다. 권한은 서버에서 확인하며 화면 숨김·역할 선택만으로 로그인/접근 제어를 구현했다고 하지 않는다.
- 실제 백엔드·알고리즘을 연결해 로그인 → 입력/설정 변경 → 실행 → 결과 → 다른 역할 조회 흐름을 확인한다. 결과가 안 달라진 경우 새 입력 반영 여부부터 검사하고 시연을 위해 숫자를 억지로 바꾸지 않는다.
- 실행 가능한 브라우저에서 정상·빈 데이터·입력 오류·실패/재시도, 긴 텍스트, 실제 작업 해상도와 좁은 화면을 확인한다. 자동화 도구가 없으면 제공 Browser로 직접 확인하고 방법을 기록한다.
- 같은 화면의 문구·간격·상태 표시를 묶어 수정한 뒤 해당 화면을 확인한다. 편집마다 전체 빌드·전체 브라우저 시나리오·스크린샷을 반복하지 않는다. 공용 컴포넌트·스타일·계약을 바꾸면 영향을 받는 화면으로 검증을 넓힌다. 전체 사용자 흐름은 첫 연결과 최종 통합 때 확인하고, 관련 조건이 그대로인 알고리즘 검증은 재사용한다. 검증 간격과 필수 검사 기준은 하네스의 `skills/verify.md`를 따른다.

핵심 기능 완성 때 구조·데이터 흐름·선택 이유·검증을 사용자에게 설명한다. 자동 검사와 사용자 직접 확인을 구분한다. 완료 결과는 실행 경로·실제 동작 근거·남은 결함이다. 미적 완성도를 위한 반복 수정이 통합·검증·제출 시간을 잠식하지 않게 한다.

원본 디자인 도구가 필요할 때만 하네스의 `guides/OPTIONAL_TOOLS.md`를 확인한다. 이 스킬은 자체 작성된 경량 절차이며 외부 플러그인의 전체 기능이나 설치를 포함하지 않는다.
