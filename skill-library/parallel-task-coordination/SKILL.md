# 작은 팀으로 작업 나누기

공식 실행 기능 위에 적용하는 개인 운영 절차다. 실제 제공 도구와 과제 규정을 우선한다. 자세한 역할 예는 저장소 루트 기준 guides/SUBAGENTS.md를 필요할 때 읽는다.

## 먼저 판단
1. 메인이 지금 직접 할 일과 독립적으로 맡길 일을 정한다. 바로 다음 단계에 필요한 짧은 작업은 직접 처리한다. 위임 후 기다리는 것밖에 할 일이 없다면 병렬화 이점이 작은지 재검토한다.
2. 네이티브 서브에이전트 도구·작업 폴더·허용 모델·권한을 확인한다. 지원이 없거나 차단됐으면 새 실행기를 설치하지 않고 순차 수행한다.
3. 첫 읽기 전용 작업 하나에서 실제 생성 ID와 결과를 확인한다. 다음부터 필요하면 자식 최대 2명까지 병렬 사용한다. 운영 권장 상한이며 플랫폼 한도가 더 작으면 그 한도를 따른다.

## 위임 계약
작업마다 다음을 전달한다. 필요하면 templates/WORK_PACKET.md를 쓴다.
- 하나의 질문 또는 산출물, 관련 요구사항과 완료 조건.
- 작업 루트·입력 파일·현재 확인된 사실·필요한 스킬 경로. 전체 대화나 모든 로그를 복사하지 않는다.
- 읽기 범위·수정 가능한 파일·테스트 출력 경로. 메인과 다른 작업자의 소유 범위를 명시한다.
- 선행 조건·반환 형식·예상 종료 시각·막힐 때 조치·추가 위임 불가.

인터페이스를 먼저 정한다. 공용 설정·잠금 파일·공유 타입은 메인이 소유한다. 두 작업자가 같은 파일을 수정하거나 공유 DB·캐시·서버 포트를 함께 바꾸지 않게 한다. 경로가 겹치면 작업을 순차화하거나 독립 작업 공간을 쓰되, 격리가 실제로 지원되는지 확인한다.

## 실행 중
- 메인은 겹치지 않는 일을 진행한다. 위임한 일을 중복 구현하지 않는다.
- 중요한 발견·계약 변경·차단 사유는 메인에게 전달한다. 단순 이름만 있던 역할에 실제 수정 권한을 임의로 늘리지 않는다.
- 실행 ID와 진행 상태는 필요할 때 templates/TASK_STATE.md에 메인이 기록한다. 시간 예산은 요청일 뿐 강제 timeout이 아니므로 실제 경과 시간을 확인한다.
- 실패 시 기존 작업이 살아 있는지 먼저 확인한다. 취소·종료 확인 전 같은 파일을 새 작업자에게 넘기지 않는다. 차단을 회피하려고 재시도하지 않는다.
- 검증 단계 이후에는 새 대규모 구현을 위임하지 않는다. 새 작업 시작 여부는 남은 통합·검증·제출 시간을 기준으로 판단한다.

## 회수와 완료
- 결과는 결론·근거 파일·변경 범위·실행 명령/결과·미해결 사항으로 받는다. 읽기 검토와 실제 실행 검증을 구분한다.
- 메인이 변경을 확인하고 통합한 뒤 핵심 흐름을 검증한다. 작업자가 완료라고 말한 것만으로 제출 가능하다고 판정하지 않는다.
- 필요한 결과를 회수한 작업자는 제공 종료 도구로 정리한다. 유지가 필요한 앱 서버나 감독 프로세스를 종료하지 않는다.
- pending 작업·미해결 필수 요구·검증 누락이 없거나 명시적으로 한계가 기록됐는지 확인한다. 제출 시점에는 미완료 작업이 파일을 바꾸지 않게 한다.
- 실제 AI 금지 후속 평가에서는 이 스킬을 사용하지 않는다.
