# 필요한 작업만 나누기

제공 기능·허용 모델·권한을 먼저 확인한다. 별도 실행기·MCP·역할 설정은 설치하지 않는다. 이 문서는 작업 조율 절차이며 실행 기능을 추가하지 않는다.

## 실행 방식 선택
- **서브에이전트:** 메인이 위임·상태 확인·결과 회수를 할 수 있고 작업 범위가 분명할 때 사용한다.
- **별도 터미널의 독립 세션:** 환경이 허용하고 사용자가 두 작업에 직접 지시·실행·확인을 이어갈 필요가 있을 때 선택할 수 있다. 사용자가 세션을 열고 공통 계약을 전달한다. 세션 간 대화·상태·모델·지침이 자동 공유된다고 가정하지 않는다.
- **순차 작업:** 선행 결과에 의존하거나 파일·자원이 겹치고 조율 비용이 큰 경우 사용한다. 서브에이전트 미지원만으로 별도 세션까지 불가능하다고 단정하지 않는다.

터미널이 둘이어도 파일 시스템·DB·캐시·프로세스가 격리된 것은 아니다. 메인과 다른 세션의 작업 경로가 같은지 확인한다. 역할은 실행 방식과 별개다.

| 역할 | 맡길 일 | 수정 권한 |
|---|---|---|
| 메인 | 요구 확정·핵심 구현·통합·최종 검증 | 공용 설정·공유 타입·잠금 파일 포함 |
| 조사 담당 | 기존 코드에서 특정 질문의 답과 근거 찾기 | 읽기 전용 |
| 검증 담당 | 독립된 요구사항·예외 검토와 테스트 | 기본 읽기 전용, 테스트 실행 시 공유 자원 충돌 확인 |
| 구현 담당(필요시) | 인터페이스가 정해진 독립 기능 | 지정한 파일만 |

1. 메인이 진행할 일과 독립적인 작업만 맡긴다. 짧은 작업이나 결과를 기다려야 다음 단계가 가능한 일은 직접 한다.
2. 서브에이전트는 첫 읽기 작업 하나로 실제 생성 ID와 결과를 확인한다. 별도 세션은 담당 역할과 실제 작업 폴더를 각각 확인한다. 처음에는 작업자 1명으로 시작하고 필요할 때만 늘린다. 권장 상한은 메인 외 2명이며 환경 한도가 우선이다. 중첩 위임은 하지 않는다.
3. 지시에는 **목표 / 작업 루트·입력 / 허용 수정 파일 / 완료 조건 / 예상 종료 시각 / 반환 형식**을 넣는다. 예: “읽기 전용으로 입력 검증 누락 3개를 찾아 파일·위치·재현 입력으로 반환. 5분 안에 확인한 범위까지만 보고. 추가 위임 금지.”
4. 같은 파일·DB·캐시·서버 포트를 동시에 바꾸지 않는다. 격리가 확인되지 않으면 순차 수행한다. 메인은 맡긴 일을 중복 구현하지 않는다.
5. 실행 ID와 상태를 확인하고, 실패·재할당 전에 기존 작업의 종료를 확인한다. 요청한 시간은 강제 timeout이 아니므로 실제 경과 시간을 확인한다.
6. 결과는 결론·근거 파일·변경 범위·실제 실행 명령/결과·미해결 사항으로 받는다. 메인이 변경을 읽고 통합 후 핵심 흐름을 실행해 검증한다. 읽기 검토를 테스트 통과로 기록하지 않는다.
7. 통합·검증·제출 시간을 남긴다. 120분 이후 새 기능 위임은 멈춘다. 제출 시 미완료 작업이 파일을 바꾸지 않도록 정리하되 앱 서버·감독 프로세스는 유지한다.
8. 실제 AI 금지 후속 평가에서는 사용하지 않는다.

## 프론트 구현과 알고리즘 테스트를 나눌 때

시작 전에 실제 경로를 정해 아래 계약을 양쪽에 전달한다. 예시 경로는 그대로 만들 의무가 없다.

| 담당 | 수정 범위 예시 | 완료 근거 |
|---|---|---|
| 프론트 세션 | UI 파일만 | 정상·빈 결과·오류 표시, 실행 경로 |
| 알고리즘 테스트 세션 | 테스트·테스트용 입력·별도 결과 폴더 | 대상 알고리즘 상태, 입력·기대값·실제값, 실패 사례 |
| 통합 담당(둘 중 지정) | API/공유 타입·알고리즘 본체·공용 설정·작업 기록 | 두 결과를 결합한 최종 흐름 |

- 공통 계약: 입출력 필드·타입·단위·정렬/동점 기준·빈 결과·오류 형식 중 해당 항목, 소유 파일, 테스트 대상 상태, 포트/출력 경로, 결과 전달 위치를 정한다.
- 계약 변경은 상대 세션에 전달하고 확인한 뒤 적용한다. 알고리즘 본체 수정이 필요하면 소유 담당에게 전달하거나 작업을 멈추고 명시적으로 소유권을 넘긴다.
- 고정한 입력·대상 코드로 테스트한다. 테스트 중 대상 코드가 바뀌면 결과가 어느 상태를 검증했는지 표시하고 최종 코드에서 다시 실행한다. 커밋 식별자가 없으면 관련 파일 스냅샷/해시 등으로 구분할 수 있다.
- 각 세션은 자기 결과만 별도 기록하고 통합 담당이 공통 문서에 합친다. 같은 로그나 문서를 동시에 덮어쓰지 않는다. 별도 세션에서는 사용자가 결과 경로와 계약 변경을 전달해야 할 수 있다.
- 양쪽 작업 완료 후 수정 중인 작업이 없는지 확인하고, 모의 응답을 실제 알고리즘으로 연결해 핵심 흐름과 예외를 다시 검증한다. 분리된 테스트의 통과만으로 통합 완료라고 하지 않는다.
