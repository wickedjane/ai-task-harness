# 예외 검토

핵심 흐름과 성공 기준을 읽고 가장 위험한 경계 조건부터 확인한다.

- 해당되는 조건을 고른다: 빈값·공백, 형식 오류, 매우 긴 값, 중복 클릭, 새로고침, 실패 후 재시도, 저장 후 다시 열기.
- 기대 결과를 먼저 정하고 실제 실행한다. 코드만 읽은 검토와 재현한 결함을 구분한다.
- 발견마다 입력/조작 → 기대 → 실제 → 영향 → 최소 수정안을 남긴다. 결함이 없으면 확인한 경로와 미검증 범위를 기록한다.
- 수정했다면 같은 재현 사례와 원래 정상 흐름을 다시 실행한다. 수행하지 않은 검증을 통과로 적지 않는다.
- 별도 검토 세션이 제공되고 시간이 충분할 때만 독립 검토를 쓴다. 불가능하면 검토 관점을 바꾸어 재확인한다.

표 형식: 사례 | 기대 | 실제 | 재현 여부 | 영향 | 조치. 새 UI가 필요하면 templates/SCREEN_STATES.md를 참고한다.
