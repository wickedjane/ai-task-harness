# 데이터 작업과 결과 검증

분석 질문·필수 산출물·성공 기준을 먼저 확인한다. 원본을 보존하고 현재 환경의 Python·SQL 등 사용 가능한 도구로 진행한다. 대규모 입력은 먼저 크기·스키마·표본 범위를 확인한다. 데이터가 있다는 이유만으로 웹 UI나 모델 학습을 추가하지 않는다.

1. **구조:** 인코딩·구분자·헤더·행 수·타입과 한 행의 의미(사용자/주문/이벤트 등)를 확인한다. 식별자의 앞자리 0을 임의로 없애지 않는다.
2. **품질:** 필수 필드 결측·키 중복·파싱 실패·범위 밖 값을 센다. 제거·보정 기준과 영향받은 행 수를 기록한다. 결측을 자동으로 0으로 바꾸거나 중복을 일괄 삭제하지 않는다.
3. **지표:** 날짜·시간대·단위·기간 경계·필터·분자/분모를 정한다. 행 수와 고유 사용자 수, 합계와 평균, 전체 비율과 그룹 비율 평균을 혼동하지 않는다. 분모 0의 처리도 정한다.
4. **조인:** 필요한 경우 키의 유일성과 1:1/1:N 관계, 미매칭·결측 키를 확인한다. 조인 전후 행 수와 관련 합계를 대조해 행 증식으로 인한 중복 집계를 찾는다.
5. **검산:** 작은 표본을 손으로 계산하고 전체 집계와 교차 확인한다. 필터·정제·집계 전후의 건수 변화를 설명한다. 표본 결과를 전체 결과로 부르지 않는다. 차트에는 기간·단위·표본 수를 적고 관찰된 상관을 인과로 단정하지 않는다.
6. **재현:** 입력 → 정제 → 집계 → 출력 순서가 드러나는 스크립트·쿼리·노트북과 실행 방법을 남긴다. 노트북은 시간이 허용하면 처음부터 순서대로 실행해 숨은 상태 의존성을 확인한다. 결과 표·차트·설명에 같은 계산 기준을 쓴다.
7. **예측 과제일 때만:** 평가 목적에 맞게 데이터 분할을 먼저 정하고 학습 데이터로만 전처리 기준을 학습한다. 동일 개체·시간·정답 정보의 누수를 확인하고 단순 기준 모델과 같은 평가 데이터로 비교한다.

필요한 단계만 적용한다. 결과에는 핵심 결론·입력 파일/테이블·사용 범위·집계식·실행 명령/결과·한계를 남긴다. 제공되지 않은 데이터나 평가 수치를 만들어 채우지 않는다. 원본 데이터는 외부로 업로드하지 않는다.

검증 전에 주장에 필요한 필드·정답 라벨·기간·희귀 사례·표본 수가 있는지 확인한다. 부족하면 ‘없는 데이터 → 확인 못한 주장 → 대체 확인 → 남는 불확실성 → 추가 검증’을 기록한다. 합성 사례의 통과는 로직 동작의 근거이며 실제 데이터의 품질·정확도·일반화 성능의 근거로 대신하지 않는다. 관측된 범위 밖의 결론은 유보한다.
