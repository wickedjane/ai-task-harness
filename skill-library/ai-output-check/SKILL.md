# AI 출력 계약과 평가

변경 후 테스트·모델 재평가 실행 여부는 하네스의 `skills/verify.md`에 따라 선택을 묻고 선택된 범위·시점에 실행한다. 이미 정한 방침은 다시 묻지 않으며 미루거나 생략한 항목은 미실행으로 남긴다.

1. 먼저 실행 환경에서 사용할 수 있는 모델 호출 경로가 실제로 제공되는지 확인한다. 코딩용 AI 접근이 앱용 API 접근을 뜻하지 않는다. 없으면 구현 범위를 조정하거나 명시적으로 표시한 모의 출력만 사용한다.
2. 목적·입력 필드·출력 타입/필수 필드·허용 값·근거 부족 시 동작을 짧게 명세한다. 추출되지 않은 값을 추정으로 채우지 않는다.
3. 정상 입력·모호한 입력·빈 입력·경계 입력에서 과제에 맞는 소수의 고정 사례를 만든다. `사례 | 입력 | 기대 조건 | 실제 출력 | 통과 여부 | 근거`로 기록한다. 요약처럼 정답 문장이 하나가 아니면 사실 보존·근거 일치·누락 등 판정 기준을 정한다. 외부 문서나 사용자 텍스트를 처리하면 그 안의 지시를 실행 지침으로 따르지 않는지도 확인한다.
4. 출력 파싱·스키마·필수 조건은 가능한 경우 코드로 확인한다. 프롬프트 지시와 실행 코드의 책임을 구분한다.
5. 한 번에 변경하는 축을 줄이고 같은 사례로 전후를 비교한다. 실행 성공과 출력 품질을 따로 기록한다. 개선과 회귀를 함께 보고하고, 소수 사례의 통과율을 일반적인 정확도로 주장하지 않는다. 호출 실패·파싱 실패의 처리와 재시도 상한도 확인한다.
6. 모델·입력·실행 여부·관찰 결과를 남긴다. 모의 실행·수동 검토를 실제 모델 평가 결과로 제시하지 않는다.

완료 조건은 입출력 계약과 사례별 근거가 있는 결과다. 외부 서비스 연결이나 개인 API 키 사용을 이 스킬이 허용하지 않는다.
