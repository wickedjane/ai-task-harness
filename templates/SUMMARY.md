# 제출 전 빠르게 훑는 구현 요약

AI가 실제 코드·설정·결정·실행 기록을 바탕으로 작성하고 갱신한다. 사용자는 제출 확정 전에 읽기만 하면 되며 직접 작성·재진술·답변 연습을 요구하지 않는다. 한 페이지, 2~3분 안에 훑을 수 있는 분량을 목표로 한다. 후속 평가에서는 파일을 볼 수 없으므로 그때 읽을 수 있다고 의존하지 않는다.

- 요약 대상 코드 상태/버전·작성 시점:
- 먼저 볼 세 줄: 무엇을 만들었나 / 핵심 선택과 이유 / 가장 중요한 한계

아래 여섯 항목은 각각 2~3문장으로, 결론과 이유를 먼저 쓰고 실제 근거를 짧게 붙인다. 세부 내용은 기존 문서·대표 파일/함수로 연결한다. 없는 근거는 미확인으로 표시한다.

## 1. 구조
(실제 기술·DB·주요 파일과 연결. HTTP API인지 내부 호출인지.)

## 2. 핵심 구현
(대표 입력이 어떤 파일/함수의 처리를 거쳐 결과가 되는가.)

## 3. 대안과 선택 이유
(실제로 고려한 대안과 선택 기준. AI 제안·사용자 결정·기록에서 확인 못한 이유를 구분하고 사후 대안은 그렇게 표시.)

## 4. 얻은 것과 포기한 것
(선택의 이점·비용·단점. 어떤 조건이면 다른 안을 고를까.)

## 5. 확인한 것
(AI 실행·사용자 직접 확인·코드 검토·미실행을 구분. 핵심 입력·기대·실제 결과와 근거.)

## 6. 한계와 다음 확인
(없는 데이터로 검증 못한 것·알려진 결함·시간/환경 제약·다음 우선순위.)

앱이 없는 과제는 실제 분석·판정 흐름과 결과 파일을 설명한다. AI가 한 일을 ‘내가 직접 확인/선택했다’고 바꾸거나, 검토하지 않은 대안을 당시 비교했다고 쓰지 않는다. 요약을 제공했다는 이유만으로 사용자 이해·검증 완료를 표시하지 않는다.
