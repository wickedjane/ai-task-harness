# 내 말로 설명하기

제출 전 학습용 메모다. 후속 평가에서는 파일을 볼 수 없다고 전제한다. 각 항목은 이해한 시점에 사용자가 자기 말로 2~3문장만 쓴다. AI는 설명과 사실 확인을 돕되 아래 문장을 대신 채우거나 덮어쓰지 않는다. 사용자가 채팅에 직접 쓴 말은 그대로 옮길 수 있다. 사실 오류는 별도 피드백을 보고 사용자가 고친다.

## 1. 구조
(실제 기술·DB·주요 파일과 연결. HTTP API인지 내부 호출인지.)

## 2. 핵심 구현
(대표 입력이 어떤 파일/함수의 처리를 거쳐 결과가 되는가.)

## 3. 대안과 선택 이유
(실제로 고려한 대안과 선택 기준. 나중에 떠올린 대안은 사후 검토라고 표시.)

## 4. 얻은 것과 포기한 것
(선택의 이점·비용·단점. 어떤 조건이면 다른 안을 고를까.)

## 5. 확인한 것
(AI가 실행한 검사와 내가 직접 확인한 것을 구분. 입력·기대·실제 결과 근거.)

## 6. 한계와 다음 확인
(없는 데이터로 검증 못한 것·알려진 결함·시간/환경 제약·다음 우선순위.)

마지막에는 이 파일을 닫고 결론 → 이유 → 구현·검증 근거 → 한계 순으로 설명해 본다. 앱이 없는 과제는 코드 구조 대신 실제 분석·판정 흐름과 결과 파일을 설명한다. AI가 설명해 줬다는 사실만으로 이해했다고 표시하지 않는다.
