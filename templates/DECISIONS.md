# 설계와 결정 기록

공식 문서가 있으면 필요한 항목만 거기에 통합한다. 실제 과제 작업 폴더에 기록하고 참고용 하네스 원본은 유지한다. 모든 수정 대신 중요한 설계·알고리즘 선택과 변경을 짧게 남긴다.

## 현재 구현의 아키텍처
- 해결하는 문제와 주요 제약:
- 구성요소 → 책임 → 실제 파일/함수:
- 대표 입력 하나가 처리·저장·출력되는 경로:
- 구성요소 사이의 계약 (입출력 형식·오류·단위 등):
- 상태/데이터 저장 위치와 유지 범위:
- 실패 시 동작과 현재 구조의 한계:

필요하면 화살표 도식 하나로 표현한다. 실제 구현과 예정인 구조를 구분하고 변경되면 갱신한다. 서버·DB·배포 구조를 실제로 쓰지 않았다면 있다고 쓰지 않는다.

## 주요 결정 (필요한 결정마다 복사)
- 결정할 문제와 당시 제약:
- 실제로 비교한 선택지와 판단 기준:

| 선택지 | 얻는 점 | 비용·위험·포기하는 점 | 현재 요구와의 적합성 |
|---|---|---|---|
| | | | |

- 선택한 안과 이유 / 선택 주체·사용자 확인 여부:
- 받아들인 단점·제외 범위와 그 영향:
- 적용 파일/함수와 확인 근거:
- 어떤 조건이 바뀌면 다른 안으로 전환할지:

당시에 비교하지 않은 대안은 ‘사후 검토’로 표시한다. AI의 제안을 사용자가 직접 선택했다고 추정하지 않는다.

## 사용자 확인과 AI 제안 검토
| 시점·기능 | AI 제안 | 사용자가 실제 확인·수정한 내용 | 이유 | 결과·근거 |
|---|---|---|---|---|
| | | | | |

사용자가 확인했다고 말한 내용만 직접 확인으로 기록한다. AI가 실행한 검증은 구분한다. 수정 없이 채택한 경우도 확인 근거를 남기며 수정 이력을 만들어내지 않는다.
