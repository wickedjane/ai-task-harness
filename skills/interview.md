# interview — 핵심 요구사항 확인

목표: 초기 15분 안에 README와 담당자 답변에서 사용자·문제·성공 기준을 파악한다. 환경 초기 확인도 이 시간 안에 포함하므로 명확한 요구사항을 반복해서 묻지 않는다.

처음에는 작업 경로·제공 파일·필요한 실행기/라이브러리만 확인하고 기존 최소 실행 명령을 시도한다. 환경변수 전체나 인증 파일은 출력하지 않는다. 실행이 막히면 오류와 대안을 짧게 기록하고 제공 도구로 진행한다. 사용하지 않을 도구까지 설치하지 않는다.

## 질문 후보
1. 누가 어떤 상황에서 사용하는가?
2. 현재는 어떻게 처리하며 가장 불편한 점은 무엇인가?
3. 어떤 흐름이 작동하면 성공이라고 보는가?
4. 반드시 필요한 것 하나와 이번에 제외해도 되는 것은 무엇인가?
5. 모호한 용어·데이터·예외 상황을 구체적인 예로 확인할 수 있는가?

주된 목적이 계획 생성, 기준에 따른 판단, 자료 분석/설명 중 무엇인지와 전달 형식(앱·표/파일·보고서/답변)을 확인한다. 계획이면 필수 조건·개선 목표, 판단이면 기준의 출처·미확인 처리·최종 결정자, 분석이면 질문·독자·근거 자료를 묻는다. 원문에 답이 있으면 재질문하지 않는다. 혼합 과제도 첫 산출물과 완료 기준 하나부터 고정하고 `skills/scope.md`에서 필요한 단계만 연결한다.

AI에게 질문 후보·모순·누락을 찾게 해도 된다. 사용자가 질문의 목적을 이해하고 우선순위를 정한다. 실제 담당자의 응답 방식에 맞춰 묻고 정해진 횟수만 채우려고 질문하지 않는다.
답변에서 확인한 사실과 내 해석·가정을 구분해서 기록한다. 핵심 흐름을 바꾸는 미확인 사항만 추가 확인하고 범위 확정으로 넘어간다.
