# scope — 범위와 설계 결정

목표: 경과 15~30분에 핵심 흐름·성공 기준·제외 범위를 정한다.

1. 공식 README·기존 코드·확인한 요구사항을 바탕으로 사용자 흐름 하나와 필요한 화면·데이터를 정리한다.
2. AI와 대안을 비교하고 최종 선택 이유·포기한 범위를 기록한다. 이미 제공된 스택·구조를 우선 활용한다.
3. 구현 예산 90분을 기준으로 위험 지점 두세 개와 검증 방법을 정한다.
4. 서버·저장소·권한은 실제 요구와 실행 환경에 맞춰 선택한다. 필요한 입력 검증·보안·오류 처리를 과설계라는 이유로 빼지 않는다.
5. 지금 쓰지 않는 추상화·기능·의존성은 줄인다. 파일 수나 특정 프레임워크를 일률적으로 제한하지 않는다.

산출물은 핵심 흐름·성공 기준·제외 범위와 주요 결정이다. 공식 문서 양식이 있으면 거기에 통합한다.

필수 요구마다 입력/동작 → 기대 결과 → 확인 방법을 연결한다. UI가 필요한 과제에만 정상·로딩·빈 데이터·오류·재시도 상태를 설계한다. 데이터 분석이나 보고서 과제라면 핵심 흐름을 입력 → 변환/분석 → 결과 검산으로 잡고 불필요한 화면·서버를 추가하지 않는다.

설계 시 구성요소별 책임·입출력 계약·상태 저장 위치·실패 처리를 실제 파일/함수에 연결한다. 대표 입력 하나의 흐름을 도식이나 몇 줄로 설명한다. 중요한 선택은 실제 대안·판단 기준·얻는 점·받아들인 단점·포기한 범위·재선택 조건을 비교한다. 필요하면 `templates/DECISIONS.md`에 기록하고 설계 변경 때 갱신한다.
핵심 설계가 정해지면 `skills/explain.md`의 중간 이해 점검을 시작한다. 전체 이해를 제출 직전에 처음 확인하지 않는다.
