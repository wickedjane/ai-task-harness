# 작업 지시와 상태 관리

모델을 직접 서빙하는 하네스와 제공된 코딩 에이전트를 사용하는 작업 지침은 적용 범위가 다르다. 여기서는 목표·입력·검증·위임·업무 상태만 관리한다. 아래는 개인 운영 권장안이며 특정 모델의 성능을 보장하지 않는다.

## 지시할 내용

한 요청에는 필요한 항목만 담는다.
- 목표와 사용할 자료: 어떤 사용자 문제를 해결하며 어떤 파일을 근거로 삼는가.
- 범위와 제약: 바꿀 수 있는 파일, 기존 계약, 제외할 기능, 시간 한도.
- 완료 기준: 결과물이 어디에 있고 어떤 실행 결과로 성공을 확인하는가.
- 반환 내용: 결정 이유, 변경 파일, 검증 명령·결과, 미해결 사항.

목표와 성공 기준은 구체적으로 적되 내부 사고 순서를 길게 지정하지 않는다. 결정을 설명하는 짧은 근거는 받는다. 같은 규칙을 AGENTS·스킬·매 요청에 반복해 길이를 늘리지 않는다. 관련 스킬과 파일만 읽힌다.

## 모델·추론 수준 선택

제공 환경이 허용한 모델과 설정만 사용한다. 처음에는 제공 기본 설정을 확인하고, 어려운 부분에서 실제 실패나 지연이 관찰될 때 한 축씩 바꾼다. 추론 수준과 최종 답변 길이는 별개다. 무조건 최대 추론, 무조건 짧은 프롬프트, 무조건 다중 에이전트를 규칙으로 만들지 않는다.

변경 전후의 완료 여부·검증 근거·대기 시간·관찰 가능한 사용량을 비교한다. 볼 수 없는 토큰·비용·실제 적용 모델은 미확인으로 둔다. 모델을 바꾸거나 세션을 재개할 때 중요한 작업 상태를 다시 확인한다.

## 업무 상태와 인수인계

작은 작업에서는 기존 PLAN·DECISIONS 기록으로 충분하다. 여러 작업자나 긴 세션이 있을 때만 templates/TASK_STATE.md를 사용한다.
확인한 사실·파일·결정·실행 결과·남은 일·진행 중 작업 ID·다음 행동을 남긴다. 전체 대화나 긴 로그를 모든 작업자에게 복사하지 않는다. 근거 파일과 필요한 부분만 전달한다.

업무 요약은 모델의 내부 추론 상태를 복원한 것이 아니다. API 이력·암호화 상태·캐시·compaction 프로토콜은 제공 런타임이 관리하는 영역이며 이 문서로 바꾸지 않는다.

## 완료와 멈춤

응답이 끝났다는 이유만으로 완료로 처리하지 않는다. 실제 산출물, 필요한 검증, 남은 필수 요구, 진행 중인 작업을 확인한다. 정상적으로 유지해야 하는 서비스 서버와 미완료 작업을 구분한다.
완료 기준을 충족하면 불필요한 리뷰·추가 기능을 시작하지 않는다. 실패를 반복하면 원인을 기록하고 범위를 줄이거나 검증 가능한 대안으로 전환한다. 계속할 때는 남은 일·예산·현재 상태를 짧게 명시한다.

독립 호출만 병렬화한다. 파일 수정 후 테스트처럼 의존성이 있는 작업, 같은 파일·캐시·포트를 사용하는 실행은 순서를 정한다. 위임할 때는 guides/SUBAGENTS.md를 읽는다.
