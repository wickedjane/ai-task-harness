## 새 환경에서 원본이 필요할 때

1. 현재 제공 도구로 못 하는 구체적인 작업을 먼저 정한다. 범용 스킬이 이미 충분하면 추가 설치하지 않는다.
2. 공식 원본에서 현재 지원 환경·버전·라이선스·의존 파일을 확인한다. SKILL.md 한 장만 복사하면 스크립트·데이터·참조 파일이 빠질 수 있다.
3. 허용된 설치 또는 공개 저장소 반입 방식으로 가져온다. CLI·환경별 경로를 확인하고 `CLAUDE_PLUGIN_ROOT` 같은 다른 환경의 변수가 존재한다고 가정하지 않는다. 기존 지침·설정을 덮어쓰지 않는다.
4. 자체 예시로 한 번 실행해 동작을 확인한다. 개인 계정·외부 API·이미지 생성 서비스가 필요한 기능은 현재 환경에서 허용·제공되는지 별도로 확인한다. 디자인 지침을 읽는 것과 외부 호출을 허용하는 것은 다르다.
5. 설치·인증·브라우저 의존성 해결에 시간이 크게 들면 기본 도구로 돌아간다. 작업 데이터·키를 외부 서비스로 전달하지 않는다.

외부 코드·테마·이미지·자료를 재배포할 때 원본의 라이선스와 고지 요건을 지킨다. 이 저장소의 두 신규 스킬은 위 자료의 용도와 일반 설계 원칙을 검토해 새로 작성한 것이며, 원본 패키지·자산·코드를 복제한 것이 아니다.
