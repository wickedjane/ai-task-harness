# 서브에이전트: 공식 기능과 이 묶음의 운영 방식

2026-10-30 공식 문서를 확인했다. 아래 공식 기능 설명과 개인 운영 권장안을 구분한다. 관리형 평가 환경의 버전·정책·모델 허용 목록이 우선하며, 해당 환경에서 실행했다는 보장은 없다.

## 이미 있는 공식 기능

Codex는 내장 default·worker·explorer 역할을 제공하며, 로컬 커스텀 역할은 프로젝트의 .codex/agents/에 TOML로 정의할 수 있다. 스킬은 반복 절차, 역할은 책임, 서브에이전트 런타임은 생성·전달·대기·종료를 담당한다. Skill Creator와 Skill Installer도 공식 도구다. 따라서 병렬 실행기를 새로 만들 필요 없이 역할과 위임 절차를 덧붙이면 된다.

공식 문서:
- [Subagents](https://learn.chatgpt.com/docs/agent-configuration/subagents): 내장 역할·프로젝트 역할·위임과 상태 관리.
- [Build skills](https://learn.chatgpt.com/docs/build-skills): SKILL.md·Skill Creator·Skill Installer·스킬 발견 경로.

## 이 묶음이 추가하는 것

`skill-library/parallel-task-coordination/SKILL.md`는 직접 작성한 개인 운영 스킬이다. OpenAI 공식 배포 스킬이 아니다. 역할·변경 범위·완료 기준·통합 책임을 정하며, 실제 생성과 실행은 이미 제공된 도구에 맡긴다.

| 담당 | 맡길 일 | 수정 범위 |
|---|---|---|
| 메인 | 사용자 소통, 범위·인터페이스 확정, 공유 설정, 통합, 최종 검증·제출 | 공용 파일과 통합 경로 |
| task_explorer | 특정 데이터·코드 경로의 사실 확인과 위험 찾기 | 읽기만 |
| task_worker | 입출력이 정해진 독립 구현 한 조각 | 명시된 파일만 |
| task_reviewer | 제출 기준 대비 결함·검증 누락 찾기 | 코드 변경 없음. 실행 검증은 사전 지정한 출력 경로만 |

세 역할을 항상 동시에 만들지 않는다. 권장 시작은 메인 + 작업자 1명이고, 독립성이 분명하면 동시 자식 최대 2명으로 늘린다. 이 숫자는 운영 권장안이며 공식 한도도 강제 런타임 설정도 아니다. 재위임은 기본적으로 하지 않는다.

## 병렬화 예

- 가능: 메인이 UI를 구현하는 동안 explorer가 고정된 입력 데이터의 필드·예외를 읽기 검토.
- 가능: 인터페이스를 정한 뒤 worker A가 한 모듈, worker B가 독립된 테스트 자료를 작성. 수정 파일·출력 경로는 겹치지 않게 지정.
- 순차: API 응답 구조를 정하기 전에 그 구조를 전제로 UI를 구현하는 작업.
- 순차: 여러 작업자가 같은 package.json·잠금 파일·라우팅·공용 타입을 수정하는 작업. 메인이 소유하거나 선행 작업 완료 후 넘긴다.
- 검증: 바뀌는 코드를 동시에 검토하면 결과에 검토한 버전을 명시한다. 최종 통합 후에는 핵심 흐름을 다시 검증한다.

## 새 환경에서 적용

1. 제공 도구에 서브에이전트 기능이 노출되고 규정상 사용 가능한지 확인한다. 지원 상태는 미확인 / 사용 가능 / 불가로 기록한다.
2. 첫 작업은 짧고 유용한 읽기 전용 조사로 시작한다. 실제 작업 ID와 반환 결과가 있어야 실행 확인이다. 생성 선언이나 역할 파일 존재만으로 성공 처리하지 않는다.
3. 모델 상속·기본값이 환경에 따라 달라질 수 있으므로 자식에게도 허용된 모델이 적용되는지 확인한다. 개인 API 키·다른 공급자·금지 모델을 끌어오지 않는다.
4. 기능이 없거나 차단됐으면 동일한 역할 지시를 한 세션에서 순차 적용한다. 관리 설정 변경·외부 CLI·API 호출로 우회하지 않는다.

## 선택형 TOML 예시

`role-examples/task_explorer.toml`, `task_worker.toml`, `task_reviewer.toml`은 최소 역할 정의다. name·description·developer_instructions만 두었고 모델·권한·MCP 설정을 고정하지 않았다. 읽기 제한은 역할 지시이며 운영체제의 강제 권한 경계가 아니다.

현재 상태에서는 자동 활성화되지 않는다. 대상 환경이 커스텀 역할과 프로젝트 파일 생성을 허용할 때만, 실제 작업 프로젝트의 .codex/agents/ 경로에 새 파일로 적용한다. 기존 역할 파일을 덮어쓰지 않는다. 내려받은 참고용 저장소 안에 두는 것만으로 원래 과제 세션에 적용됐다고 가정하지 않는다.

이미 시작한 세션의 새 역할 발견 여부도 별도로 확인한다. 등록이 불필요하거나 지원되지 않으면 내장 역할에 같은 지시를 전달한다. 하네스가 자동 등록·동시 실행을 강제하지 않는다.

## 지시 예시

제공 Codex 안에서 다음 취지로 요청한다:

> parallel-task-coordination 스킬을 읽고 이 과제의 독립 작업만 나눠줘. 기능과 허용 모델을 먼저 확인해. 메인은 범위와 통합을 맡고, 읽기 전용 탐색 1명부터 시작해. 구현을 나누면 파일 소유권과 완료 기준을 지정하고 자식은 동시에 최대 2명까지만 운용해. 지원되지 않으면 순차로 진행해.

역할 설명만 주지 말고 templates/WORK_PACKET.md의 입력·경로·완료 조건을 실제 과제에 맞게 채운다. 실제 서술형 평가가 시작된 뒤에는 어떤 역할도 AI 답안 작성에 사용하지 않는다.
