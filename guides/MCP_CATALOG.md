# MCP 후보와 도입 기준

2026-10-30 공식 저장소 문서를 확인했다. 아래는 추천 후보이며 관리형 응시 환경에서 설치·실행이 검증됐다는 뜻이 아니다. 해당 환경의 허용 범위와 실제 도구를 우선한다.

| 후보 | 기본 판단 | 필요한 상황 | 대안·조건 |
|---|---|---|---|
| 제공 터미널·파일·Browser | 우선 사용 | 실행·파일 수정·서비스 확인 | MCP 추가 없이 짧은 실제 작업 확인 |
| Playwright MCP | 조건부 1순위 | 웹 UI의 반복 입력·상태 전환을 자동 검증 | 내부 Browser 수동 확인으로 충분하면 생략. Node 18+와 브라우저 실행 환경 필요 |
| Context7 | 이번 기본 묶음에서는 비활성 | 낯선 라이브러리의 버전별 문서 조회 | 외부 서버로 질의를 보내며 인증이 관여할 수 있음. 허용된 공개 문서 접근 경로 우선 |
| Filesystem MCP | 대개 불필요 | 제공 도구에 파일 접근이 없을 때 | 터미널·기본 파일 도구와 중복. 필요하면 작업 디렉터리만 허용 |
| Fetch MCP | 조건부 | 제공 AI에 공개 문서 조회 수단이 없을 때 | 공개 URL의 읽기만 허용되는지 확인. 문제·코드·결과를 요청에 실어 보내지 않음 |
| Sequential Thinking MCP | 기본 제외 | 별도의 사고 상태 관리가 실제로 필요할 때 | 작은 PLAN·DECISIONS 기록으로 시작 |
| 개인 GitHub·Drive·Notion·Figma 연결 | 기본 제외 | 명시적으로 허용된 연동 과제일 때만 | 로그인·개인 자격증명·외부 쓰기 부담. 공개 저장소 반입에는 GitHub MCP가 필요 없음 |
| 내부 검색·로그·사내 위키 연결 | 제외 | 이 범용 묶음의 범위 밖 | 사내 네트워크·자격증명·데이터에 의존 |

## Playwright 후보 설정

`mcp/playwright.optional.json`은 공식 패키지 실행 방식에 headless·isolated 옵션을 붙인 예시다. 자동 적용하지 않는다. 제공 MCP UI가 받는 JSON 구조와 허용 범위를 확인하고 필요한 경우에만 해당 항목을 병합한다. 기존 설정 전체를 교체하지 않는다.

- `@latest`는 고정 버전이 아니다. 사전 체험에서 확인한 버전이 있으면 그 버전으로 고정한다.
- 도구 목록이 보이는 것과 브라우저가 실행되는 것은 다르다. 본인이 만든 로컬 서비스에서 입력 하나와 결과 하나를 확인한다.
- 내부 서비스만 대상으로 한다. 외부 개인 브라우저·기존 로그인 세션·감독 화면에 연결하지 않는다.
- 브라우저 바이너리·시스템 의존성 설치가 필요하거나 접속이 차단되면 제한을 우회하지 않는다. 3분 안에 확인되지 않으면 기본 Browser로 돌아가는 것을 개인 운영 기준으로 권한다.
- MCP가 실행한 브라우저가 플랫폼 Browser와 동일한 세션이라고 가정하지 않는다. 최종 확인은 제공 Browser에서도 수행한다.

`mcp/empty.json`은 아무 서버도 등록하지 않은 형식 예시다. 기존 설정을 초기화하는 용도가 아니다.

## 외부 요청과 자료 반입 구분

공개 도구를 내려받을 수 있다고 그 도구로 비공개 과제 데이터를 외부 서버에 보내도 되는 것은 아니다. 특히 문서 검색 도구에 전체 과제·코드·오류 로그를 붙여 넣지 않는다. 관리형 환경에서는 허용된 호출 경로와 데이터 범위를 확인한다.

## 공식 출처
- [Microsoft Playwright MCP](https://github.com/microsoft/playwright-mcp): 실행 요구사항·구성·격리 프로필. CLI 기반 방식도 공식 문서가 대안으로 안내한다.
- [Context7](https://github.com/upstash/context7): 문서 조회·질의 도구·인증 설정.
- [MCP reference servers](https://github.com/modelcontextprotocol/servers): Filesystem·Fetch·Sequential Thinking 등 참조 구현. 운영 환경에 바로 적용할 완제품이라는 보장은 없다.
