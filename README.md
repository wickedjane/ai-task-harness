# AI Task Harness

180분 실무형 과제의 요구 확인 → 구현 → 검증 → 제출 전 이해 점검을 돕는 작은 지침 모음입니다. 공식 시험 자료나 문제·정답이 아닙니다.

## 시작

공개 저장소 반입이 허용된 **응시 환경 안의 코딩 에이전트**에게 다음과 같이 요청합니다. 공개 저장소이므로 GitHub 로그인은 필요 없습니다.

```text
https://github.com/wickedjane/ai-task-harness 를 참고용 하위 폴더에 clone해 줘.
하네스의 AGENTS.md와 PLAN.md를 읽고 과제 원문과 기존 지침을 우선해 줘.
현재 시각·시간대를 실제로 확인하고 실제 시작·플랫폼 마감·남은 시간을 기록해 줘.
준비 중이면 실제 시작 전에는 타이머를 시작하지 말고, 재개라면 기존 시작 시각을 이어 써.
PLAN의 이정표마다 지금 무엇을 끝내고 다음 무엇으로 전환해야 하는지 알려줘.
실제 코드는 원래 과제 공간에, 필요한 기록은 그 안의 docs/에 두고 경로를 알려줘.
테스트 방침은 skills/verify.md에 따라 시작 때 확인하고 내가 정한 방침을 유지해 줘.
핵심 구현과 선택 이유를 중간에 설명하고 SUMMARY는 내가 내 말로 쓰게 도와줘.
이후 문서는 지금 단계에 필요한 것만 읽어 줘.
```

에이전트가 실행할 명령 예시:

```sh
git clone --depth 1 https://github.com/wickedjane/ai-task-harness.git ai-task-harness
```

같은 폴더가 이미 있으면 내용을 확인하고 덮어쓰지 않습니다. clone만으로 지침이 자동 적용된다고 가정하지 않고 `ai-task-harness/AGENTS.md`와 `ai-task-harness/PLAN.md`를 명시적으로 읽힙니다. 외부 브라우저 접속·개인 파일 업로드를 요구하지 않습니다. 반입이 차단되면 우회 설치에 시간을 쓰지 말고 과제 원문과 제공 도구로 진행합니다.

총 22개 파일이며 처음 읽는 진입 문서는 2개입니다. 이후 테스트 방침 등 필요한 단계와 과제에 맞는 보조 스킬만 읽습니다. 평가 보고서 도구는 Python 표준 라이브러리만 사용합니다. MCP·모델·역할 설정은 없습니다. 절차 문서와 선택 스킬은 필요할 때 파일을 직접 읽으면 되며 설치하지 않아도 됩니다. 보조 스킬은 자체 작성물입니다.

## 작업 기록 위치

템플릿은 참고용 하네스 안에 있고 작성한 기록은 **실제 과제 작업 폴더**에 둡니다. 공식 양식이 있으면 통합하고, 아래 파일을 전부 만들 필요는 없습니다. 경로가 이미 사용 중이면 내용을 보존하고 합치거나 다른 경로를 알립니다.

| 기본 경로 | 내용·작성 주체 |
|---|---|
| docs/REQUIREMENTS.md | 요구사항, 실제 시작·마감·시간대, 테스트 방침 — 메인 |
| docs/DECISIONS.md | 실제 구조·선택 이유, 진행·핸드오프·소유권 — 메인/통합 담당 |
| docs/VERIFY.md | 검사 대기·실행 근거·미검증·한계 — 통합 담당이 취합 |
| docs/EVALUATION.md | 비교·판정·주장 근거 — 기존 결과에 없을 때만 |
| docs/README.md | 실행/열람 방법·핵심 결과·기록 위치 — AI가 정리, 사용자 확인 |
| docs/SUMMARY.md | 구조·구현·선택·절충·검증·한계를 내 말로 — 사용자, AI는 사실관계 피드백 |

‘작업 기록’은 진행·결정이면 DECISIONS, 검사 대기·결과면 VERIFY를 뜻합니다. 원문 README를 산출물 README로 덮어쓰지 않습니다. SUMMARY는 제출 전 학습용이며 후속 평가에서 파일을 열람할 수 있다고 가정하지 않습니다. 실제 기록 경로를 정해 모든 세션에 전달합니다.

## 목적별 흐름과 산출물

| 주된 목적 | 핵심 흐름 | 먼저 완성할 산출물 |
|---|---|---|
| 계획 생성 | 조건 확인 → 기준안 → 개선/비교 → 선택 | 실행 가능한 계획·배정, 미처리 사유, 적용 조건과 지표 |
| 품질·위험 판단 | 기준 확인 → 항목별 판정 → 근거/미확인 → 검토 | 적합·부적합·미확인 표, 근거, 추가 확인 사항 |
| 자료 분석·설명 | 질문/자료 확인 → 계산/검색 → 결론과 근거 연결 | 표·차트·보고서/답변, 출처·계산, 가정과 한계 |

상세 절차는 `skills/scope.md`에 있습니다. 실제 요구에 맞는 주된 목적 하나부터 정하고 혼합 과제는 필요한 단계를 연결합니다. 전달 형식은 앱·파일·보고서 중 필요한 것을 선택합니다. 제품의 입력/권한/업무 규칙과 개발 후 테스트 실행 여부는 구분합니다.

데이터·AI 출력 스킬은 일반 개발 절차에서 놓치기 쉬운 검증 기준이 있어 포함했습니다. 환경 점검·예외 재현·화면 상태·통과 기준은 기존 단계 문서에 통합했습니다. 원본 플러그인은 선택 가이드에 출처·용도·조건만 안내하고 코드·자산을 포함하거나 자동 설치하지 않습니다. 커스텀 역할 TOML과 중복 양식은 포함하지 않습니다.

구조도는 실제 과제 코드에 맞춰 작성합니다. 어떤 DB·알고리즘 파일·함수를 쓰는지, 어떤 연결이 HTTP API이고 어떤 연결이 내부 함수/DB 접근인지 표시합니다. 기존 문서의 Mermaid 미리보기 또는 외부 연결 없는 SVG/HTML로 확인하고 구현 대응표를 함께 읽습니다. 구조가 바뀐 변경 묶음 후와 최종 통합 때 갱신합니다. 양식은 `templates/DECISIONS.md`에 있으며 도식을 위한 추가 도구는 기본 설치하지 않습니다.

## 테스트 방침

시작 시 지속 방침 확인, 변경 후 선택, 실행 간격·근거 재사용의 정본은 `skills/verify.md`입니다. 필요한 기록 칸은 `templates/VERIFY.md`에 있습니다.

## 평가 보고서 예제

아래는 실제 성능을 주장하지 않는 합성 CSV로 형식을 확인하는 예제입니다. 하네스 루트에서 실행합니다.

```sh
python3 scripts/compare_runs.py examples/runs.synthetic.csv --baseline base --metric cost:min --metric quality:max --output /tmp/evaluation-example.html
```

결과는 외부 통신 없는 HTML로 저장됩니다. 파일 미리보기가 지원되지 않으면 같은 폴더를 제공 환경에서 허용한 로컬 서버로 열거나 표를 확인합니다. 실제 과제에서는 측정한 CSV와 새 출력 경로를 사용합니다. 이 도구는 AUC 계산기나 제약 검증기가 아니며, 원본 실행에서 계산한 지표를 비교합니다. CSV 형식과 지표 선택은 evaluation-design 스킬에 있습니다.

비교 도구 코드를 수정했을 때의 검증: `PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tests -v`. 과제 UI나 지침 문서를 바꿀 때마다 이 도구의 테스트를 반복할 필요는 없습니다.

템플릿은 필수 제출물이 아닙니다. 기존 과제 README·AGENTS.md·공식 양식을 유지하고 필요한 기록만 통합합니다. 후속 평가 시간·문항 수·규칙은 실제 안내를 따릅니다. AI 금지 후속 평가에서는 직접 답합니다.
